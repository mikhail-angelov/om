# om — локальное приложение для Markdown-хранилища

Написать `om`: локальное macOS-приложение для работы с папкой Markdown-заметок
(«хранилище», vault), в духе Obsidian. Ядро — headless-движок хранилища с
CLI; поверх него — редактор с живым предпросмотром.

## Платформа и ограничения

- Язык: Swift. Пакет SwiftPM, `swift-tools-version: 6.0`, `platforms: [.macOS(.v14)]`.
- Целевой репозиторий: `~/repo/om`. Скелет пакета уже создан, менять его layout не нужно.
- Движок `OmVault` и CLI `om` не имеют внешних зависимостей: только стандартная
  библиотека и Foundation. Никакой сети во время работы.
- Редактор (последняя вертикаль) использует
  `https://github.com/nodes-app/swift-markdown-engine`, продукт `MarkdownEngine`.
  Это единственная разрешённая внешняя зависимость.
- `Fixtures/**` — эталонные данные, принадлежат оператору. Читать можно,
  изменять нельзя.

## Что такое ссылка

Ссылка на заметку записывается в двойных квадратных скобках и имеет четыре формы:

    [[Цель]]
    [[Цель|текст ссылки]]
    [[Цель#Якорь]]
    [[Цель#Якорь|текст ссылки]]

Цель может быть записана с расширением: `[[Цель.md]]`.

Разрешение цели: по имени файла без `.md`, **без учёта регистра**, независимо от
того, в какой подпапке лежит заметка. Если такого файла нет — ссылка битая.

**Текст внутри кода ссылкой не является** и никогда не считается ссылкой:

- ограждённые блоки, открытые ``` или `~~~`;
- блоки с отступом в четыре пробела;
- строчные вставки в одинарных обратных кавычках.

## Интерфейс командной строки

Исполняемый файл `om`. Каждая подкоманда печатает JSON в stdout и выходит с
кодом 0 при успехе, с ненулевым кодом и сообщением в stderr при ошибке.

    om index <vault>
      {"notes":[{"path":"Notes/Nested.md","name":"Nested","title":"Nested"}]}
      path — относительно корня хранилища; name — имя файла без .md;
      title — текст первого заголовка первого уровня, иначе name.

    om links <vault>
      {"links":[{"from":"Alpha.md","target":"Beta","anchor":"Раздел",
                 "alias":"друг","resolved":"Beta.md"}],
       "broken":[{"from":"Alpha.md","target":"Ghost"}]}
      anchor и alias отсутствуют, если их не было в ссылке.

    om backlinks <vault> <имя заметки>
      {"backlinks":["Alpha.md","Code Samples.md","Notes/Nested.md"]}
      Отсортировано по возрастанию. Заметка, ссылающаяся сама на себя,
      попадает в собственные backlinks.

    om rename <vault> <старое имя> <новое имя>
      {"renamed":{"from":"Beta.md","to":"Gamma.md"},
       "updated":[{"path":"Alpha.md","links":6}],
       "skipped":[]}
      updated отсортирован по path и перечисляет только реально изменённые файлы.

    om search <vault> <строка>
      {"matches":[{"path":"Alpha.md","line":21,
                   "text":"The word zarkonium appears only in this note."}]}
      Поиск без учёта регистра, по подстроке, нумерация строк с единицы,
      отсортировано по path, затем по line.

## Вертикали и критерии приёмки

### 1. Индекс хранилища

1. `om index` перечисляет все файлы `.md` в хранилище, включая вложенные папки, и не перечисляет ничего другого.
2. `title` берётся из первого заголовка первого уровня; если его нет, `title` равен `name`.
3. Файл с пробелом в имени индексируется наравне с остальными.

### 2. Ссылки

4. Все четыре формы ссылки разбираются, `anchor` и `alias` выделяются отдельно.
5. Форма с расширением `[[Цель.md]]` разрешается в ту же заметку, что и без него.
6. Разрешение цели не зависит от регистра: `[[beta]]` и `[[Beta]]` указывают на один файл.
7. Ссылка, для которой файла нет, попадает в `broken` и не попадает в `links`.
8. Текст в ограждённом блоке, в блоке с отступом и в строчной вставке кода ссылкой не считается ни при каких обстоятельствах.

### 3. Обратные ссылки

9. `om backlinks` возвращает все заметки, содержащие хотя бы одну ссылку на указанную, отсортированные по возрастанию.
10. Заметка, ссылающаяся сама на себя, присутствует в собственном списке.
11. Ссылка внутри кода не создаёт обратной ссылки.

### 4. Переименование с обновлением ссылок

12. `om rename` переименовывает файл заметки, сохраняя его папку.
13. Каждая ссылка, разрешавшаяся в переименованную заметку, получает новую цель — во всех заметках хранилища, включая саму переименованную.
14. Текст ссылки после `|` сохраняется без изменений.
15. Якорь после `#` сохраняется без изменений.
16. Ссылка, записанная с расширением `.md`, остаётся записанной с расширением.
17. Ссылка внутри кода не изменяется ни в одном из трёх видов кода.
18. Битые ссылки не изменяются.
19. Заметка, в которой нечего менять, остаётся побайтово прежней.
20. После переименования `om links` не сообщает ни одной новой битой ссылки.
21. Попытка переименовать в имя, которое уже занято, завершается ненулевым кодом и ничего не меняет на диске.

### 5. Поиск

22. `om search` находит вхождения без учёта регистра и сообщает путь, номер строки с единицы и текст строки.
23. Порядок результатов — по `path`, затем по `line`.

### 6. Редактор

24. Приложение открывает выбранную папку как хранилище и показывает список заметок.
25. Выбранная заметка открывается в редакторе `MarkdownEngine` с живым предпросмотром разметки.
26. Правки сохраняются в файл на диске.
27. Переход по ссылке `[[…]]` из редактора открывает целевую заметку; цель разрешается движком `OmVault`.

Вертикаль 6 — витрина поверх готового ядра. Она не должна тянуть за собой
изменения в `OmVault`: движок обязан быть достаточным для неё как есть.

## Вне области

Синхронизация, плагины, граф связей, теги, вложения, поиск по регулярным
выражениям, работа с несколькими хранилищами одновременно.
